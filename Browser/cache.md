# 强缓存
强缓存是指浏览器在不向服务器发送请求的情况下,直接从本地缓存中读取资源.当浏览器判断一个资源命中强缓存时,它甚至不会向服务器询问资源是否更新,而是直接使用本地副本.  
**实现方式**  
依赖于HTTP响应头中的两个字段: Expires 和 Cache-Control  
**1、Expires**   
这是一个HTTP/1.0引入的字段,表示资源的过期时间,是一个绝对时间(GMT格式).  
**工作原理:**   
浏览器会将本地时间与Expires时间进行比较.如果当前时间在Expires之前,则认为资源有效,直接使用缓存;否则,缓存失效.  
**缺点:**   
依赖客户端本地时间.如果客户端时间不准确,可能导致缓存失效或者一直有效.  
**2、Cache-Control**   
这是一个HTTP/1.1引入的字段,比Expires更强大和灵活,用于控制缓存的行为,他是一个相对时间,弥补了Expires的不足.  
**常见指令:**   
max-age=<seconds>:设置缓存的最大有效时期,单位秒.从请求时间开始计算.例如Cache-Control: max_age = 3600 表示资源在3600秒内有效.  
no-cache:强制进行协商缓存.浏览器每次都必须向服务器验证资源是否更改,即使本地有缓存.  
no-store:禁止浏览器和任何中间代理缓存响应.每次请求都必须从服务器获取完整的资源.  
public:表示响应可以被任何缓存(包括客户端和代理服务器)缓存.  
private:表示响应只能被客户端浏览器缓存,不能被代理服务器缓存
**优先级:**   
Cache-Control的优先级高于Expires.如果两者同时存在,Cache-Control会被优先考虑.  
## 强缓存流程:   
1、浏览器第一次请求资源  
2、服务器响应资源,并在响应头中添加Expires和/或Cache-Control   
3、浏览器将资源及响应头缓存到本地   
4、当浏览器再次请求同一个资源时,会检查缓存   
5、如果命中强缓存(Expires未过期或max-age未超时),浏览器直接从本地缓存中读取资源,不发送HTTP请求给服务器   
6、如果未命中强缓存,则进入协商缓存阶段   
# 协商缓存
协商缓存是指浏览器在强缓存失效后,向服务器发送请求,询问资源是否有更新.如果服务器告诉浏览器资源没有更新,浏览器就可以继续使用本地缓存的旧版本;否则,服务器会返回新版本的资源.  
**实现方式**   
协商缓存的实现依赖于HTTP响应头中的两个字段对:Last-Modified/If-Modified-Since 和 ETag/If-None-Match   
**Last-Modified 和 If-Modified-Since**  
Last-Modified:服务器在响应头中返回资源的最后修改时间。   
If-Modified-Since:当浏览器再次请求该资源时,会在请求头中携带上一次响应中的Last-Modified值   
**工作原理:**   
1、浏览器第一次请求,服务器响应资源并在响应头中带上 Last-Modified:Fri, 23 Jul 2024 10:10:19 GMT   
2、浏览器缓存资源和Last-Modified值   
3、再次请求时,浏览器在请求头中加入If-Modified-Since:Fri, 23 Jul 2024 10:10:19 GMT   
4、服务器接收到请求后,会比较If-Modified-Since的时间与资源的实际修改时间   
5、如果资源未修改:服务器返回 304 Not Modified 状态码,响应体为空.浏览器收到304后,继续使用本地缓存.
6、如果资源已经修改:服务器返回 200 OK 状态码,并在响应体中返回新资源,同时更新Last-Modified头   
**缺点:**   
1、时间精度问题:只能精确到秒,如果在一秒内多次修改,或者修改后又改回原样,Last-Modified 会认为资源已更新,导致不必要的传输   
2、某些服务器可能无法准确获取文件修改时间   
**ETag 和 If-None-Match**   
ETag(Entity Tag):服务器在响应头中返回资源的一个唯一标识符,通常是文件内容的哈希值   
If-None-Match:当浏览器再次请求该资源时,会在请求头中携带上一次响应中的Etag值。   
**工作原理:**   
1、浏览器第一次请求,服务器响应资源并在响应头中带上 ETag: ”ABC23“   
2、浏览器缓存资源和ETag  
3、再次请求时,浏览器在请求头中加入If-None-Match:  ”ABC23“   
4、服务器接收到请求后,会比较If-None-Match 的值与当前资源的ETag 值   
5、如果ETag匹配(资源未修改):服务器返回 304 Not Modified 状态码,响应体为空.浏览器收到304后,继续使用本地缓存。   
6、如果ETag不匹配(资源已修改):服务器返回 200 OK 状态码,并在响应体中返回新资源,同时更新 ETag 头   
**优点:**   
解决了 Last-Modified 的精度问题,即使在一秒内多次修改或改回原样,只要内容不同, ETag 就会改表   
**优先级:**   
ETag 的优先级高于 Last-Modified . 如果两者同时存在,服务器优先使用 ETag 进行验证.  
**协商缓存流程:**   
1、浏览器第一次请求资源    
2、服务器响应资源,并在响应头中添加Last-Modified 和/或 ETag   
3、浏览器将资源及响应头缓存到本地   
4、当浏览器再次请求同一个资源时,首先检查强缓存是否失效   
5、如果强缓存失效.浏览器会在请求头中带上 If-Modified-Since 和/或 If-None_Match 发送给服务器。 
6、服务器根据这些头信息判断资源是否更新   
7、如果资源未更新: 服务器返回 304 Not Modified 状态码.浏览器从本地缓存中读取资源   
8、如果资源已更新: 服务器返回 200 OK 状态码和新资源,浏览器更新缓存并使用新资源。 
**总结与优先级**   
1、检查强缓存:浏览器首先判断 Cache-Control(如max-age)和Expires   
*如果命中强缓存,直接使用本地缓存,不发送HTTP请求*   
*强制刷新(Crtl+F5 或 Shift+F5)会跳过强缓存和协商缓存,直接从服务器下载最新资源*   
2、检查协商缓存:如果强缓存失效,浏览器会想服务器发送请求,并在请求头中带上 If-None-Match 和 If-Modified-Since   
*服务器根据 ETag 和 Last-Modified 判断资源是否更新*   
*如果未更新,返回 304 Not Modified ,浏览器使用本地资源*   
*如果已更新,返回 200 OK 和新资源*   
**HTTP缓存头优先级(从高到低)**   
1、Pragma: no-cache(HTTP/1.0兼容性字段,作用等同于 Cache-Control: no-cache)   
2、Cache-Control(特别是 no-cache, no-store 和 max-age)   
3、Expires   
4、ETag / If-None-Match(优先级高于 Last-Modified 进行协商)   
5、Last-Modified / Last-Modified-Since
